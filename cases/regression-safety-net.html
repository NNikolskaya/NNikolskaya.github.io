02 / Legacy modernization · Testing

Building a regression safety net before modernizing a live platform

A production telecom application on Java 11 and Spring Boot 2.7 needed modernization. With almost no automated tests, a broad framework upgrade could break existing behavior silently. A new integration with a closed external system made the testing gap immediate.

Context

Manual regression testing carried most of the verification burden. The external SOAP dependency could not be used freely in development, so the new integration required a controlled local test setup.

The constraint

The first tests worked locally but the existing CI environment was not ready for them. I kept the business feature moving, then used a later engineering window to turn the local setup into reusable testing infrastructure.

What I did

  1. Reconstructed and documented the application’s important flows from the legacy codebase.
  2. Set a test strategy around behavior: unit tests, integration tests, and Testcontainers where real infrastructure mattered; excluded boilerplate from coverage targets.
  3. Enabled test execution in GitLab CI and added a coverage gate to preserve the new baseline.

Outcome

Meaningful automated coverage rose from approximately zero to about 80%. The service gained repeatable regression checks and a safer foundation for future Java and Spring upgrades. The broader platform upgrade was still in preparation when this case was recorded.

Trade-off

The feature need came first; the broader CI work was scheduled separately so a platform-wide improvement did not block immediate delivery.
