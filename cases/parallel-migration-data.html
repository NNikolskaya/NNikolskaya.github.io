04 / Distributed systems · Data consistency

Keeping data consistent while two platforms ran in parallel

A large distribution platform was moving core behavior from a legacy system into Java microservices. Users would migrate gradually, which meant both platforms had to operate at the same time without diverging on critical operational data.

Context

Inventory, lot, and order-reservation information changed on both sides of the migration boundary. Undocumented legacy behavior also had to be translated into requirements for the new services.

The constraint

A one-time data copy would become stale immediately. Synchronization had to handle updates in both directions and avoid a change bouncing endlessly between systems.

What I did

  1. Worked with business analysts, QA, and legacy engineers to turn undocumented behavior into validated service requirements.
  2. Designed and implemented Kafka-based bidirectional synchronization using database-change capture and application events.
  3. Used origin-aware filtering to prevent synchronization loops during parallel operation.

Outcome

The old platform and new microservices ran in parallel as users moved gradually. The synchronization handled thousands of events per day and kept critical operational data aligned during the transition.

Trade-off

Parallel operation created additional moving parts, but it reduced migration risk by allowing a phased change instead of a single cutover.
